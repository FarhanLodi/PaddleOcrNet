# Multi-page document evidence

`DocumentAssembler.Assemble(IEnumerable<DocumentPage>)` builds a `DocumentStructure` from existing per-page structure results. Supply original one-based page numbers (gaps allowed) and any unmatched OCR lines in `OrphanLines`. Duplicate page numbers are rejected. Every original page, block, text value, formula, table HTML, cell bound and orphan line remains available. `ToJson()` uses source generation and includes the full evidence instead of the compact page export DTO.

Relationships reference original page numbers and original block indices, not potentially repeated reading-order numbers. Sequence links follow each page's existing `Order`, preserving RTL and column decisions already made by the layout engine. Strict containment links identify the smallest enclosing block, but do not claim semantic ownership. Overlapping siblings remain separate.

Repeated-header candidates require header labels, identical whitespace-normalized text, the top 15% of each page and horizontal alignment within 3% of page width. Table-continuation candidates require consecutive original page numbers, a table reaching the bottom 15% followed by one beginning in the top 15%, aligned horizontal edges and matching parsed column counts of at least two. Evidence additionally records whether first-row text matches. These relationships require review: even matching headers and columns do not prove that two tables belong together. Assembly never merges HTML, removes headers, changes raw text or fills missing cells.

The structure engine retains whole-page OCR lines with no reliable single layout owner in `StructureResult.OrphanLines`. This includes source readings split across multiple blocks, so failed or partial fragment recognition cannot erase the original evidence. Orphans share the result's coordinate frame and appear in compact and full JSON; existing Markdown/HTML rendering does not silently insert them into blocks. Document assembly automatically merges engine orphans with caller-supplied `DocumentPage.OrphanLines`, deduplicating equivalent geometry/text/confidence evidence while preserving conflicting readings and raw structures. It cannot recover text discarded before the structure result was supplied. A caller can use the links and orphan evidence to build a reviewed view while retaining `Pages` as source evidence. The heuristic thresholds are conservative engineering defaults, not validated confidence estimates. `DocumentAssemblyTests` and `StructureOrphanTests` cover preserved RTL order, orphan JSON/assembly and actual engine retention, nested formulas, repeated headers, table boundaries, page gaps and rejection of ambiguous alignment.

Stage diagnostics now include `pdf_render` (PDF read/extraction/render), `layout` (detector execution), `table` (complete region processing, including lazy model setup), and `formula` (formula pass, including lazy setup). These are wall-clock scopes, can overlap, include failure time, and do not include document content in tags.

Structure results also expose `Coordinates`, containing original dimensions and the rotation and nonlinear unwarp actually applied. Structure geometry remains on the preprocessed image; unlike the OCR-only API, structure rotation is not mapped back. `IsOriginalFrame` is false after rotation or unwarp. `InverseMappingAvailable` is false after nonlinear unwarp because the model emits pixels without an inverse field; after rotation alone the original dimensions and rotation describe the affine inverse. This history is included in both compact structure JSON and full document JSON. Null metadata means a legacy or externally constructed result with no declared history, not proof of an original-source frame.

## Explicitly confirmed table views

After reviewing continuation evidence, pass only approved relationships to `document.CreateJoinedTables(approvedLinks)`. The API returns separate `DocumentTableView` objects; it never modifies raw page blocks or HTML. Approval must reference candidates already present in the document, form chains without duplicate or branching links, and connect adjacent original pages. Table columns and first-row text/column spans must match. No candidate is joined merely because the assembler inferred it.

Each output cell retains its logical column, column span and row span. Rows retain original page/block references and original zero-based row indices. The first row of later tables is omitted only in the view, and its complete row appears in `OmittedHeaders`. This log makes every omission inspectable. Body rowspans remain within their original table; spans crossing table boundaries or involving the repeated first row are rejected. Header mismatches, holes, overlapping spans, malformed markup and nested tables fail explicitly rather than flattening data.

The strict joiner accepts well-formed table XML/HTML, including optional row groups and quoted span attributes. Unlike tolerant renderers, it does not repair HTML, infer omitted cells or interpret HTML-only entities. XML DTDs and external entities are disabled. Inline markup is represented as decoded text (`br` becomes a newline); exact markup remains in the source blocks. `DocumentTableJoiningTests` verifies confirmed multi-page chains, source row mapping, merged cells, omission logs, mismatches, invalid spans and topology, and preservation of the raw tables.
