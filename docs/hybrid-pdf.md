# Hybrid PDF text extraction

Set `PdfOcrOptions.TextLayer = PdfTextLayerMode.Hybrid` on extraction, streaming, or searchable-PDF calls. The existing Ignore, PreferEmbedded and Auto modes retain their behavior.

Hybrid reads native glyphs, rejects lines with invalid characters or non-finite/empty geometry, and performs visual OCR. Sparse valid native labels are allowed; the page-wide 20-character gate does not apply. It reconciles candidates in rendered-page pixel coordinates using rectangle overlap and normalized text. Matching native duplicates are removed. Comparable overlapping native and OCR lines select native text and preserve the visual reading in `PdfPageResult.LineEvidence`; different normalized readings set `HasConflict`. Native selection is a deterministic preference, not proof that native text is correct. Consumers should review conflicts. Native confidence 1 remains a legacy sentinel, not a probability.

`PdfPageSource.Mixed` means the selected output contains both sources. `LineEvidence` has one entry for each selected output line and preserves source and alternatives. Searchable PDF output uses selected lines only, so retained alternatives are not inserted as overlapping selectable text. OCR/native regions with substantially different extents are kept rather than deleting potentially unique content. Line segmentation differences can therefore still yield partial duplication; this is deliberately conservative. The initial reading order is top-to-bottom then left-to-right, not inferred multi-column or RTL structure.

`NativeCoverageRatio` measures clipped union area, so overlapping invisible layers cannot inflate coverage above one. The canonical `CoordinateFrame` is `rendered-page-pixels`: top-left origin, X right, Y down, at the result DPI. PDFium applies page rotation and crop geometry to its device coordinates. Multiplying by 72/DPI yields points on the rendered page, not original PDF user-space coordinates. OCR maps its orientation corrections back to the original raster before fusion. Caller `RecognitionOptions.Region`, including normalized regions, also filters native candidates; only fully contained native lines are admitted.

The default performs full-page visual OCR (or the caller's explicit region). Native glyph coverage alone cannot establish that images contain no text, nor validate a plausible but wrong native reading. Hybrid adds evidence and text completeness opportunities; it does not claim a measured accuracy or speed improvement.

For explicit selective scheduling, set `PdfOcrOptions.HybridRecognizeUncoveredOnly = true` together with `TextLayer = Hybrid`. This first calls `DetectRegionsAsync` on the source raster and recognizes only uncovered detector polygons with `RecognizeRegionsAsync`. A detected region is considered covered only when the union of valid native line rectangles covers at least 95% of it. Each contributing native box must overlap by at least half its own area, so an oversized native paragraph does not suppress a small detected region merely through containment. Duplicate native layers do not multiply coverage. A small header inside a larger detector region does not suppress recognition of the larger region. Caller languages, character controls, detection settings and Region pass through unchanged; native and detected boxes outside the requested Region are excluded.

Selective mode requires explicit `RecognitionOptions` with `UseDocOrientation = false`, `UseDocUnwarp = false`, and every preprocessing flag disabled, including `Preprocessing = new PreprocessingOptions { CorrectNonSquarePixels = false }`. The source-region APIs cannot apply page transformations consistently to native glyph coordinates; incompatible settings are rejected before rendering rather than ignored. Text-line orientation may still run within recognized crops. A custom service must implement both detection and region recognition; unsupported implementations receive an informative error instead of falling back silently.

When selective mode selects native text, `PdfPageResult.NativeTextVisualVerificationSkipped` is true. This explicitly records that a full-page visual verification pass was skipped, even when no detector region needed recognition. Plausible wrong native text may therefore escape conflict detection; missed detector regions are also a completeness limitation. Keep the default full-page path when conflicts or weak native layers must be checked. No detector thresholds, CER gains, throughput gains or native-layer correctness probabilities have been validated for this scheduling option. `PdfUncoveredRecognitionTests` covers coverage unions, partial coverage, explicit controls, unsupported services and public PDF pipeline defaults with deterministic services.

Normalization uses NFC and collapses whitespace runs while preserving case, compatibility characters and word boundaries. Disagreements in these properties remain conflicts. Fusion and searchable overlays reject OCR results explicitly marked as lacking a source-coordinate mapping; disabling nonlinear unwarping restores the supported coordinate contract.

Conflicting native layers also produce one selected line with alternatives; `AlternativeSources` identifies each alternative's source. Malformed UTF-16 native readings are rejected. Hybrid supports Line and Word grouping and explicitly rejects Paragraph grouping, whose merged regions would lose per-line evidence. Plain extraction with unmapped nonlinear coordinates declares `dewarped-page-pixels` rather than claiming source-raster coordinates.

`PdfHybridTests` checks sparse headers over OCR content, retained conflicts, duplicate native layers, overlap-correct coverage, invalid geometry/text, vertical region preservation, source-mapping rejection, and real PDFium/API integrations with deterministic visual results. `PdfHybridIntegrationTests`, gated by `PADDLEOCRNET_RUN_INTEGRATION=1`, uses actual OCR of a bundled receipt to create a scan with a duplicated stale native layer, then checks Hybrid conflict retention, missing scan text, deduplication and PDFium selectable-glyph alignment. These are correctness tests, not an accuracy benchmark or validation of rotated native glyph grouping.


`PdfUncoveredIntegrationTests` adds gated real detector/recognizer validation: exact native-covered detector polygons are omitted from recognition, remaining receipt text is recognized in source coordinates, and the public selective Hybrid PDF path preserves scan text while disclosing unverified native selection. These tests verify scheduling and geometry, not native-text accuracy or performance gains.
